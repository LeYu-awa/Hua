# 花溯 Agent 开发对接文档

> 面向对象：Agent / Rust 后端 / AI 推理 / 画布智能 / 墨迹回放开发者  
> 产品名：花溯  
> 文档版本：v1.0  
> 日期：2026-06-26

---

## 1. 文档目的

最初产品讨论的是“单文档墨迹回放”，现在花溯已经升级为：

> **多人协作的无限画布写作伴侣。**

因此，Agent 的职责也从“分析一个人的写作过程”，扩展为：

> **理解一群人在无限空间中的协作、创作、停顿、分歧、聚合与成长。**

这份文档的目标是让 Agent 开发者清楚：

- Agent 是什么。
- Agent 要处理哪些数据。
- Embedding、LLM、RAG、规则引擎分别用在哪里。
- 哪些能力先做，哪些能力后做。
- Rust Agent 架构如何逐步落地。
- 如何让 Agent 既智能，又不打扰用户。

---

## 2. Agent 是什么

Agent 是花溯的大脑。

它实时分析画布上的内容与行为，理解：

- 画布上有什么。
- 用户正在做什么。
- 多人之间如何协作。
- 用户在哪里卡住。
- 哪些内容可能有关联。
- 当前讨论处于发散、收敛还是停滞。

然后，Agent 把洞察转化成：

- 画布提示。
- 回放标注。
- 写作诊断。
- Live2D 动作。
- Live2D 对话。
- 协作建议。
- 复盘报告。

最终目标不是让用户觉得“有一个 AI 在监控我”，而是让用户感觉：

> **有一个懂我、不烦人、偶尔能给出惊喜的写作伙伴在陪着我。**

## 3. 数据来源

Agent 的数据主要来自三层：画布数据、操作流、协作信息。

| 数据层   | 包含内容                                       | Agent 用途                                             |
| -------- | ---------------------------------------------- | ------------------------------------------------------ |
| 画布数据 | 节点、连线、标注、分组、位置、时间戳           | 理解“画布上有什么”，用于空间聚类、隐含连接、空白区识别 |
| 操作流   | 光标移动、键盘输入、删改、跳转、选中、粘贴     | 理解“用户怎么写的”，用于停顿检测、风格分类、写作诊断   |
| 协作信息 | 用户身份、多人操作重叠、光标交汇、共同编辑区域 | 理解“团队怎么协作的”，用于角色识别、共识/分歧检测      |

## 4. Agent 能力全景图

Agent 能力按优先级分为三层：

1. 短期 MVP：必须有，优先落地。
2. 中期差异化：形成产品护城河。
3. 长期深度推理：构建完整 Agent 体系。

---

## 5. 短期 MVP：必须先有

短期目标不是追求“真正智能”，而是让用户能明显感知到：

> 花溯正在记录、回放、理解我的写作过程。

| 能力             | 具体场景                                                              | 实现方式      | 涉及术语          |
| ---------------- | --------------------------------------------------------------------- | ------------- | ----------------- |
| 操作流采集与存储 | 记录所有人的操作：打字、移动、删改、画节点、连线等，按时间存入 SQLite | 纯工程，无 AI | Event Stream      |
| 墨迹回放引擎     | 像视频播放器一样拖拽进度条，重播任意时间段的写作过程                  | 纯工程，无 AI | Sequence Modeling |
| 基础统计面板     | 显示字数变化曲线、删改率、停顿时长、编辑频次分布                      | 纯工程，无 AI | Metrics           |
| 停顿检测与触发   | 光标在同一位置停 2 分钟，Live2D 温和提示                              | 规则引擎      | Rule-based System |

### 5.1 停顿提示示例

不推荐：

```text
检测到您已停顿 120 秒。
```

推荐：

```text
卡在这里了？要不要先写下一句，不一定非要按顺序来。
```

## 6. 中期差异化：核心智能能力

中期目标是把 Agent 从“规则触发”升级为“理解内容关系”。

| 能力                     | 具体场景                                                                             | 实现方式                      | 涉及术语                                |
| ------------------------ | ------------------------------------------------------------------------------------ | ----------------------------- | --------------------------------------- |
| 语义相似度与隐含连接推荐 | 用户 A 写“用户调研数据”，用户 B 画“痛点分析框图”，位置很远但语义相关，Agent 推荐连线 | Embedding + 余弦相似度        | Embedding / Semantic Similarity         |
| 画布空间聚类             | 画布上散落 50 个节点，Agent 聚成“需求分析”“技术方案”“用户反馈”“竞品研究”四个话题簇   | Embedding + 空间索引 + DBSCAN | Vector Search / Clustering              |
| 语义空白区识别           | 画布讨论了技术可行性和成本估算，但缺少用户接受度，Agent 主动提醒                     | Embedding + 向量空间分析      | Semantic Search                         |
| 注意力热点检测           | 多人集中在同一区域反复编辑，Agent 判断这是当前焦点议题                               | 规则 + 空间统计               | Awareness                               |
| 写作风格分类             | 判断用户是渐进完善型、顶层设计型还是发散跳跃型                                       | 规则 + 统计特征分类           | Behavior Modeling / User Profiling      |
| 情绪状态推断             | 删改率飙升、频繁撤销、短时高频操作，Agent 推断用户可能烦躁                           | 规则引擎 + 特征融合           | Affective Computing / Anomaly Detection |

## 7. 长期护城河：AI 深度推理

长期目标是让 Agent 不只是“分析数据”，而是能进行开放场景判断。

| 能力           | 具体场景                                                                                           | 实现方式                       | 涉及术语                                                |
| -------------- | -------------------------------------------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------- |
| 共识/分歧检测  | 用户 A 写“方案 X 可行”，用户 B 标注“成本过高”，用户 C 补充“有预算弹性”，Agent 判断这是争议还是补充 | Embedding + LLM 推理           | Embedding / LLM / RAG                                   |
| AI 主动干预    | 卡顿、跑偏、疲劳、进度压力、情绪低落等场景下，Agent 判断是否该出现、怎么说、说多久                 | LLM + 规则决策 + 时机策略      | Prompt Engineering / Intervention Timing / Tool Calling |
| 个性化写作档案 | 跨项目形成用户写作 DNA：风格类型、最佳时段、完美主义指数、常见卡点                                 | Embedding + RAG                | User Profiling / Vector Database                        |
| AI 复盘报告    | 写作结束后生成《今日写作复盘》，包含流畅度、卡顿、修改热点、高光时刻                               | LLM + 数据聚合 + 叙事生成      | Reflection / Prompt Engineering                         |
| 跨项目模式发现 | 发现用户写技术文档时总是先画架构图，再写正文，并在新项目中主动提醒                                 | Embedding + RAG + 时序模式挖掘 | Sequence Modeling / RAG                                 |

## 9. 推理流程示例：隐含连接推荐

以“隐含连接推荐”为例，完整链路如下：

```text
1. 用户 A 在画布左上新建节点：
   “用户调研数据显示 80% 用户需要实时同步”

2. 用户 B 在右下新建节点：
   “实时同步功能开发排期约 3 周”

3. 事件流进入 Agent 调度器。

4. Agent 调用 Embedding API：
   节点 A 文本 -> 向量 a
   节点 B 文本 -> 向量 b

5. 计算余弦相似度：0.87，高度相关。

6. 同时检测空间距离：
   A 在 (100, 200)，B 在 (800, 600)，距离较远。

7. 规则判断：
   相似度 > 0.7 且 距离 > 100px -> 触发隐含连接推荐。

8. Agent 调用 LLM 生成自然语言提示：
   “你们一个在聊用户需求，一个在聊开发排期——这两件事好像是一起的，要不要连起来看看？”

9. Agent 通过 IPC 通知前端：
   画布显示虚线连接 + 提示气泡。

10. 同时通知 Live2D 小人探头提示。
```

设计原则：

> 毫秒级采集，异步 AI 推理，非阻塞 UI 反馈。用户不应该感觉到“卡”，只应该感觉到“它好懂我”。

## 10. Embedding、LLM、RAG、规则引擎分工

| 任务类型               | 使用技术               | 为什么这样选                                     | 在花溯里的体现                  |
| ---------------------- | ---------------------- | ------------------------------------------------ | ------------------------------- |
| 判断两段文字意思有多近 | Embedding + 余弦相似度 | LLM 成本高、延迟大，Embedding 适合批量计算       | 画布大量节点两两相似度计算      |
| 判断共识还是分歧       | Embedding + LLM        | Embedding 只能算“近不近”，LLM 判断“对立还是互补” | 协作争议节点/共识区识别         |
| 生成人情味提示语       | LLM                    | Embedding 不能生成新文本                         | Live2D 台词、复盘报告、诊断描述 |
| 判断用户当前状态       | 规则引擎               | 情绪信号可规则化，响应更快                       | 删改率异常、频繁撤销、疲劳预警  |
| 识别画布缺了什么视角   | Embedding + LLM        | Embedding 发现语义空洞，LLM 命名空洞             | “你们没讨论用户接受度”          |
| 个性化写作建议         | RAG + LLM              | RAG 先检索历史档案，LLM 再生成建议               | “综合你过去 12 篇文档……”        |

### 10.1 核心原则

| 技术      | 特点                     | 用途                         |
| --------- | ------------------------ | ---------------------------- |
| Embedding | 快、便宜、适合大规模计算 | 语义检索、相似度、聚类       |
| 规则引擎  | 最快、零成本、确定性强   | 停顿检测、疲劳预警、情绪信号 |
| LLM       | 慢、贵，但能推理和生成   | 复杂判断、对话生成、报告叙事 |
| RAG       | 让 LLM 不靠记忆硬编      | 个性化、跨项目、减少幻觉     |

一句话原则：

> **Embedding 高频调用，LLM 只在需要推理和生成时调用，规则引擎过滤掉 80% 不需要 AI 的场景。**

## 11. 技术选型速查

| 技术项            | MVP 方案                      | 产品化方案                | 涉及术语                     | 选型理由                               |
| ----------------- | ----------------------------- | ------------------------- | ---------------------------- | -------------------------------------- |
| Embedding 模型    | OpenAI text-embedding-3-small | 本地 ONNX / BGE 系列      | Embedding / ONNX             | MVP 快速验证，后续迁本地保隐私、降成本 |
| LLM 推理          | GPT-4o-mini                   | OpenAI + 本地 Ollama 混用 | LLM / Ollama                 | MVP 用云端，长期混合架构降低成本       |
| 向量存储          | 内存索引                      | SQLite-vector / Qdrant    | Vector Database / RAG        | MVP 画布关闭即释放，产品化做跨项目检索 |
| RAG 实现          | 简单上下文拼接                | 向量检索 + Prompt 注入    | RAG / User Profiling         | MVP 快速跑通，后期构建用户写作档案     |
| 规则引擎          | 硬编码 if-else                | 可配置规则集              | Rule-based System            | 初期快速迭代，后期灵活调整             |
| Rust Agent 运行时 | 直接调用 API 或 Python 后端   | 自建 Rust 推理引擎        | Tool Calling / Orchestration | 长期技术护城河，降低 Python 依赖       |

## 12. 分阶段落地计划

### 12.1 Phase 1：数据基础 + 规则引擎

周期：2-3 周。

| 任务                     | 涉及技术          | 说明                  |
| ------------------------ | ----------------- | --------------------- |
| 事件流数据结构设计与存储 | SQLite            | 设计 schema，写入事件 |
| 前端埋点接入             | Event Tracking    | 所有操作上报          |
| 墨迹回放引擎 V1          | Sequence Modeling | 时序重播              |
| 基础统计面板             | Metrics           | 字数、删改率、停顿    |
| 停顿检测 + 规则触发      | Rule-based System | 停顿 2 分钟触发提示   |

对 Agent 开发者要求：

> 纯工程能力，不需要 AI 经验。重点是数据建模、存储读写、事件驱动架构。

---

### 12.2 Phase 2：Embedding + 画布语义理解

周期：4-6 周。

| 任务                     | 涉及技术                 | 场景举例                                 |
| ------------------------ | ------------------------ | ---------------------------------------- |
| Embedding 集成           | Embedding / ONNX         | Rust 调 OpenAI API，文本转向量           |
| 语义相似度与隐含连接推荐 | Semantic Similarity      | 左上“用户调研”和右下“痛点分析”推荐连线   |
| 空间聚类 + 热点检测      | Vector Search / 空间索引 | 50 个节点聚成 4 个话题簇                 |
| 语义空白区识别           | Semantic Search          | 讨论很多技术和成本，发现没讨论用户接受度 |
| 注意力热点检测           | Awareness                | 右上角编辑密度高，标记为焦点区域         |

对 Agent 开发者要求：

> 熟悉 Embedding API 调用、向量计算、余弦相似度、聚类算法。无需深度学习，但要知道怎么用向量做语义计算。

---

### 12.3 Phase 3：LLM + 多人协作推理

周期：4-6 周。

| 任务          | 涉及技术                 | 场景举例                                             |
| ------------- | ------------------------ | ---------------------------------------------------- |
| 多人数据融合  | Time Alignment           | 多用户时间线对齐，判断同一时间谁在做什么             |
| 角色识别      | Behavior Modeling        | A 持续发起新节点是发起者，B 总在别人节点备注是深化者 |
| 共识/分歧检测 | Embedding + LLM          | 判断两段相似文本是对立还是互补                       |
| 协作阶段判断  | 规则 + 统计              | 新增节点速度 > 连接速度 = 发散期                     |
| LLM 对话生成  | LLM / Prompt Engineering | 写完 2000 字后生成一句温暖庆祝语                     |

对 Agent 开发者要求：

> 熟练使用 LLM API，能够做 Prompt 编排，能设计统一的人情味 System Prompt，并理解 RAG 基本原理。

---

### 12.4 Phase 4：主动干预 + 个性化 + 养成

周期：4-6 周。

| 任务            | 涉及技术                                | 场景举例                           |
| --------------- | --------------------------------------- | ---------------------------------- |
| 情绪推断        | Affective Computing / Anomaly Detection | 删改率飙升 + 频繁撤销 -> 焦虑信号  |
| 多场景主动干预  | Intervention Timing / Tool Calling      | 判断要不要说、什么时候说、说什么   |
| 个性化写作档案  | User Profiling / Vector Database        | 历史文本形成用户风格向量           |
| AI 复盘报告生成 | LLM / Reflection                        | 每次写作结束生成《今日写作复盘》   |
| 养成体系接入    | 规则 + LLM                              | 经验值、等级、亲密度随写作行为成长 |

对 Agent 开发者要求：

> 需要综合使用规则、Embedding、LLM、RAG。最核心能力是干预时机，这决定用户觉得 Agent 是贴心还是烦人。

---

### 12.5 Phase 5：Rust Agent 运行时

长期方向。

| 任务                     | 涉及技术                     | 说明                                                    |
| ------------------------ | ---------------------------- | ------------------------------------------------------- |
| 自建 Rust Agent 推理引擎 | Tool Calling / Orchestration | 替代 Python Agent 框架，降低延迟和打包体积              |
| 本地 Embedding 迁移      | ONNX / Candle                | 完全离线，用户数据不出设备                              |
| 本地 LLM 集成            | Ollama / Candle              | 本地处理简单推理，云端处理复杂推理                      |
| 多 Agent 协作            | Multi-Agent System           | 画布 Agent、写作诊断 Agent、陪伴 Agent 由调度器统一协调 |

对 Agent 开发者要求：

> 需要 Rust 系统编程能力 + AI 推理工程经验。这是真正的技术护城河。

## 16. 输出风格规范

Agent 不是冷冰冰的统计系统，而是有温度的写作伙伴。

### 16.1 语言原则

- 温柔。
- 克制。
- 不命令。
- 不评判。
- 不心理诊断。
- 不频繁打断。
- 先观察，再建议。

### 16.2 不推荐表达

```text
检测到您已停顿 120 秒。
检测到您的删改率异常。
您当前处于焦虑状态。
建议您立即修改第三段。
```

### 16.3 推荐表达

```text
卡在这里了？要不要先把下一句写出来，不必按顺序来。

这段你停留得比较久，可能是在找一个更准确的说法。

这里好像是今天的一个转折点，要不要我帮你在回放里标一下？

你刚才一口气写完了这一段，而且几乎没改，很像今天的高光片段。
```

## 17. 给 Agent 开发者的一句话

你的工作不是做一个“会聊天的 AI”，而是：

> **用 Rust 搭建一个调度层，把 Embedding、LLM、RAG 和规则引擎编排起来，让用户在使用画布和回放时，感受到一个懂我、不烦人、偶尔惊喜的写作伙伴在陪着自己。**

其中：

| 技术                | 在花溯中的意义                                           |
| ------------------- | -------------------------------------------------------- |
| Embedding           | 让机器读懂画布上的文字内容，用于相似度、聚类、空白区分析 |
| LLM                 | 让机器说出有人情味的话，用于对话、报告和复杂判断         |
| RAG                 | 让 Agent 记住用户写作历史，用于个性化和跨项目分析        |
| 规则引擎            | 让 Agent 快速响应明确信号，如停顿、疲劳和删改异常        |
| User Profiling      | 让 Agent 越用越懂用户，是养成体系的数据基础              |
| Affective Computing | 让 Agent 感知用户可能的状态，但不能武断诊断              |
| Intervention Timing | 决定 Agent 什么时候出现，是“不烦人”的核心策略            |

最终目标：

> **先把简单的事做得足够好，再逐步叠加更难的智能。每一步都要有可交付的用户价值，而不是画饼。**
