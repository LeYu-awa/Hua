## 1. 产品概述

### 1.1 一句话定义

花溯是一个**面向写作过程的、有人情味的桌面写作伴侣**，其 Agent 系统是一套**以写作过程为中心的多智能体协作分析引擎**，在不打扰用户的前提下，实时感知写作状态、回顾写作历程、促进协作共识。

### 1.2 产品定位

传统写作工具关注"产出"（文档本身），花溯关注"你是怎么写出来的"。Agent 系统是这一理念的智能层——不是发号施令的助手，而是坐在旁边的同桌：看得见你的状态、记得住你的习惯、在你需要的时候轻轻推一把。

### 1.3 核心价值

| 维度           | 价值主张                                   |
| -------------- | ------------------------------------------ |
| **过程可视化** | 写作过程的每一笔都可回放、可追溯、可理解   |
| **智能感知**   | 实时感知情绪、节奏、卡顿，但不越界打扰     |
| **协作增强**   | 多人共创中自动识别共识、分歧、接力点       |
| **习惯沉淀**   | 跨项目的写作画像，让用户看见自己的成长     |
| **降级可用**   | 无 AI 能力时规则引擎仍可工作，永不空转报错 |

## 2. 目标用户

### 2.1 核心用户群

| 用户类型           | 特征                             | 核心诉求                                       |
| ------------------ | -------------------------------- | ---------------------------------------------- |
| **个人写作者**     | 日记、随笔、技术文章、小说创作者 | 回放写作过程、识别卡顿模式、获得温柔的写作反馈 |
| **协作创作者**     | 多人共笔、头脑风暴、方案讨论     | 共识检测、语义空白区提醒、接力追踪             |
| **注重隐私的用户** | 对数据敏感，偏好本地优先         | 全本地推理（Tauri + SQLite + 可选 LLM）        |
| **审美敏感用户**   | 追求工具的情绪价值和视觉体验     | Live2D 花灵驱动、氛围感知、非侵入式交互        |

### 2.2 用户场景

- **场景一**：写完一篇长篇笔记后，打开墨迹回放看写作过程，标记自然标注出"纠结""停顿""流畅"节点
- **场景二**：夜深了，写作删改率异常升高，花灵在状态栏轻轻问"要不要休息一下"
- **场景三**：共笔画布上 A 和 B 对方案产生分歧，Agent 自动标注分歧区，花灵提示"你们在这个点上好像还没对齐"
- **场景四**：多人接力写作，回放 timeline 自动识别接力点，给每人打上角色标签
- **场景五**：想回顾这周写作状态，Agent 生成一份复盘报告，附带历史同类文档的对比

## 3. 产品哲学与设计原则

### 3.1 核心原则

| 原则       | 说明                                                                               |
| ---------- | ---------------------------------------------------------------------------------- |
| **可降级** | 无 AI/Embedding 供应商时，所有分析器返回空/null，UI 静默不报错；规则分析器始终可用 |
| **可忽略** | 每条 Agent 建议都可被 dismiss，忽略后不再展示同类建议                              |
| **不打扰** | 冷却机制确保同类提示不会高频发生；建议优先级排序，低优先级被高优先级覆盖           |
| **能复用** | 所有分析器为纯函数，不耦合 UI，可独立测试和复用                                    |
| **可追溯** | 每条指令、每条标记都有源头事件 ID，支持全链路追踪                                  |

### 3.2 设计约束

- **本地优先**：所有核心功能和数据存储在本地（SQLite + 文件系统），AI 调用为可选增强
- **异步非阻塞**：所有 AI/Embedding 调用异步执行，不阻塞 UI 线程
- **纯函数分析**：分析器无副作用，输入 = 事件列表，输出 = 分析结果
- **克制的输出**：任何 Agent 输出都假设可能被用户忽略，不依赖用户回应

### 4.3 数据流

```
用户操作 → 原始事件（Ink/Canvas/Chat）
  → events.ts 归一化为 AgentEvent
  → Rust event_store 持久化
  → 各分析器订阅/轮询 AgentEvent 流
  → 分析结果 → SignalQueue（冷却+去重+排序）
  → 分发给订阅方（UI 组件 / Live2D 花灵 / Replay 时间轴）
```

## 5. 功能需求

### 5.1 事件标准化层（P0）

| 功能              | 描述                                                                  | 优先级 |
| ----------------- | --------------------------------------------------------------------- | ------ |
| F1.1 Ink 事件归一 | 将 InkEvent（insert/delete/select/cursor/paste）归一为统一 AgentEvent | P0     |
| F1.2 画布事件归一 | 将 CanvasNode 的 create/update/delete 归一为 AgentEvent               | P0     |
| F1.3 连线事件归一 | 将 CanvasEdge 的 create 归一为 AgentEvent                             | P0     |
| F1.4 聊天事件归一 | 将协作聊天消息归一为 AgentEvent                                       | P0     |
| F1.5 滑动窗口过滤 | 提供 eventsInWindow() 返回时间窗口内的事件子集                        | P0     |
| F1.6 事件文本提取 | 统一提取事件文本内容用于语义分析                                      | P0     |

**验收标准**：

- 所有事件类型均可双向转换（事件 → AgentEvent → 还原）
- 单条事件归一化耗时 < 0.1ms
- 窗口过滤 10 万条事件 < 5ms

### 5.2 规则引擎（P0）

| 功能                  | 描述                                          | 优先级 |
| --------------------- | --------------------------------------------- | ------ |
| F2.1 冷却追踪器       | 按 key 记录上次触发时间，避免同类提示反复打扰 | P0     |
| F2.2 阈值判断         | 值 >= 阈值时才触发，支持可配置阈值            | P0     |
| F2.3 去重             | 按 keyFn 去重，稳定排序，保留首次出现         | P0     |
| F2.4 优先级排序       | 按 priority 降序排序，同优先级保持稳定        | P0     |
| F2.5 冲突检测（Rust） | 检测两条规则是否匹配同一事件类型+动作         | P1     |
| F2.6 热更新（Rust）   | 运行时替换规则列表，无需重启                  | P1     |

**验收标准**：

- 冷却准确度：冷却期内 canFire() 返回 false，期外返回 true
- 去重覆盖所有 AgentUICommand 类型
- 优先级排序始终稳定，不依赖插入顺序

### 5.3 信号队列（P0）

| 功能              | 描述                                           | 优先级 |
| ----------------- | ---------------------------------------------- | ------ |
| F3.1 统一指令类型 | AgentUICommand 可辨识联合，涵盖所有 Agent 输出 | P0     |
| F3.2 入队控制     | enqueue 带冷却检查，在冷却内返回 false 丢弃    | P0     |
| F3.3 批量分发     | flush 按优先级排序后分发给全部订阅者           | P0     |
| F3.4 即时分发     | dispatch = enqueue + flush 一步完成            | P0     |
| F3.5 订阅机制     | subscribe 返回 unsubscribe 函数                | P0     |
| F3.6 队列重置     | reset 清空队列和冷却状态                       | P1     |

**指令类型**：

| 指令类型                | 说明               | 默认优先级 | 默认冷却 |
| ----------------------- | ------------------ | ---------- | -------- |
| `suggest_connection`    | 建议画布节点建连   | 50         | 15s      |
| `show_semantic_gap`     | 提示语义缺失视角   | 30         | 10min    |
| `show_discussion_panel` | 展示共识/分歧面板  | 80         | 60s      |
| `distill_chat_node`     | 建议聊天沉淀为节点 | 40         | 20s      |
| `archive_suggest`       | 建议归档一组节点   | 20         | 60s      |
| `live2d_signal`         | 花灵情绪/气泡信号  | 60（自带） | 30s      |
| `replay_marker`         | 回放时间轴标记     | 10         | 0        |

**验收标准**：

- 冷却期内同类型指令被正确丢弃，冷却期外正常通过
- 高优先级指令始终先于低优先级分发
- 10 万次 enqueue/flush 循环 < 100ms

### 5.4 情绪与焦虑检测（P1）

| 功能              | 描述                                                | 优先级 |
| ----------------- | --------------------------------------------------- | ------ |
| F4.1 实时情绪推断 | 基于最近 1 分钟事件推断：流畅/纠结/停顿/平静        | P0     |
| F4.2 情绪颜色映射 | 每种情绪映射一个视觉色值                            | P0     |
| F4.3 焦虑指数计算 | 相对个人基线的加权倍数，含删改率/光标/停顿 3 个指标 | P1     |
| F4.4 个人基线管理 | 自动学习个人行为基线，含默认基线兜底                | P1     |
| F4.5 干预建议     | 焦虑指数超过阈值时触发干预建议                      | P1     |

**情绪判定规则**：

| 条件                          | 结果                    |
| ----------------------------- | ----------------------- |
| 事件为空                      | 平静 - "准备开始"       |
| 60s 无事件且超过 30s          | 停顿 - "休息一下也可以" |
| 插入 > 5 次且删改比 < 0.2     | 流畅 - "状态不错"       |
| 删改比 > 0.4 或光标 > 插入 2x | 纠结 - "在反复打磨"     |
| 其他                          | 平静 - "稳定输出中"     |

**焦虑指数计算**：

```
指标：deleteRatio / cursorPerMin / pausePerMin
权重：0.4 / 0.3 / 0.3（和为 1）
指数 = Σ(当前指标 / 个人基线指标 × 权重)
阈值：>= 2.0 触发干预建议
```

### 5.5 共识/分歧检测（P1）

| 功能                  | 描述                                       | 优先级 |
| --------------------- | ------------------------------------------ | ------ |
| F5.1 Embedding 向量化 | 将观点文本转为向量                         | P0     |
| F5.2 相似度矩阵       | 两两计算余弦相似度                         | P0     |
| F5.3 连通分量聚类     | 基于阈值聚簇                               | P0     |
| F5.4 桥梁节点发现     | 识别跨组中等相似的观点                     | P1     |
| F5.5 共识状态判定     | 单组=共识，多组+桥梁=混合，多组无桥梁=分歧 | P0     |
| F5.6 Discord UI 指令  | 输出 show_discussion_panel                 | P1     |

**判定逻辑**：

```
consensusThreshold = 0.85（可配置）
divergeThreshold   = 0.55（可配置）
minOpinions        = 3（可配置）

聚类：相似度 >= 0.85 的观点为同组
桥梁：与其他组最大相似度在 [0.55, 0.85) 之间
状态：
  - 1 组 → consensus
  - 多组且有桥梁 → mixed
  - 多组无桥梁 → diverging
```

### 6.4 冷却与降级策略

```

  └─ 在冷却期外 →
       ├─ 有 AI 供应商 → 调用 LLM 增强分析
       └─ 无 AI 供应商 → 纯规则分析（可降级）
            ├─ 可分析 → 输出结果
            └─ 不可分析 → 返回 null（调用方兜底为"暂无可展示的内容"）
```

## 7. 交互逻辑

### 7.1 非侵入式交互规则

| 规则       | 说明                                                             |
| ---------- | ---------------------------------------------------------------- |
| **不弹窗** | 所有 Agent 输出以覆盖层/气泡/状态栏/标记点形式呈现，永不弹 Modal |
| **可忽略** | 每条建议都有关闭/忽略操作，忽略同类不重复提示                    |
| **不催促** | 冷却机制确保同类型提示不会在短期内重复                           |
| **不报错** | AI 调用失败不显示错误 Toast，分析器返回空时 UI 静默              |

## 9. 性能指标

### 9.1 客户端性能

| 指标                        | 目标        | 测量方式                 |
| --------------------------- | ----------- | ------------------------ |
| 事件归一化延迟              | < 0.1ms/条  | performance.mark         |
| 情绪检测延迟                | < 5ms/次    | 60s 窗口过滤 1000 条事件 |
| 冷却检查延迟                | < 0.01ms/次 | JS 对象查找              |
| SignalQueue enqueue         | < 0.05ms/次 | 包括冷却检查             |
| SignalQueue flush（50 条）  | < 1ms       | 稳定排序                 |
| Rust 事件写入               | < 5ms/条    | SQLite INSERT            |
| Rust 事件查询（500 条）     | < 20ms      | SQLite SELECT + JOIN     |
| Rust 分析编排（500 条事件） | < 50ms      | 规则引擎 + 标记生成      |
| Embedding 调用（10 条文本） | < 500ms     | 网络请求，受供应商影响   |
| LLM 调用（复盘报告）        | < 10s       | 网络请求，受供应商影响   |

### 9.2 内存与存储

| 指标                    | 目标                           |
| ----------------------- | ------------------------------ |
| 单条事件内存占用        | < 1KB                          |
| 单条建议内存占用        | < 2KB                          |
| 信号队列最大 pending 数 | < 200 条（超过则丢弃低优先级） |
| SQLite 单会话最大事件数 | 50 万（超过触发自动归档）      |
| 历史文档档案大小        | < 10MB（按文档数 \* 2KB 估算） |

### 9.3 可降级场景

| 场景                | 表现                                         | 影响范围                       |
| ------------------- | -------------------------------------------- | ------------------------------ |
| 无 Embedding 供应商 | consensus / semanticGap 返回 null，UI 静默   | F5/F6 不可用                   |
| 无 LLM 供应商       | writingReport 抛异常，semanticMarkers 返回空 | F8.2/F9 不可用，规则标记仍可用 |
| SQLite 写入失败     | 重试 3 次（25/50/75ms 间隔），仍失败则丢弃   | 事件丢失                       |
| 单次事件批量 > 500  | 截断到 500 条                                | 分析窗口受限                   |
| SignalQueue 满      | 丢弃低优先级指令                             | 部分 UI 指令丢失               |

## 10. 约束与边界

### 10.1 技术约束

| 约束        | 说明                            |
| ----------- | ------------------------------- |
| 前端框架    | React + TypeScript              |
| 桌面框架    | Tauri v2                        |
| 后端语言    | Rust                            |
| 本地存储    | SQLite（rusqlite）              |
| AI 调用方式 | HTTP REST API（用户自配供应商） |
| 事件采集    | 纯本地，不经过网络              |
| Live2D 驱动 | CSS 精灵 + Canvas 渲染          |

### 10.2 安全约束

| 约束         | 说明                                         |
| ------------ | -------------------------------------------- |
| 隐私         | 所有事件数据存储在本地，不上传               |
| AI 数据      | AI 调用内容由用户自主配置，应用不代收        |
| 敏感内容过滤 | LLM Prompt 在被发送前检查敏感词              |
| 安全审计     | 所有 SQL 查询使用参数化查询，无 SQL 注入风险 |

### 10.3 体验边界

| 边界               | 处理方式                                             |
| ------------------ | ---------------------------------------------------- |
| 用户从不点击"分析" | 仅情绪检测和焦虑指数自动运行，画布分析需用户主动触发 |
| 用户完全离线       | 规则分析器全部可用，LLM/Ebedding 功能跳过失          |
| 10 人同时协作      | 接力检测 O(n²) 在 10 人时仍在可接受范围              |
| 单次写作 10 万事件 | 分析窗口限制为最近 500 条，历史数据存档              |

## 12. 术语表

| 术语                | 说明                                                                              |
| ------------------- | --------------------------------------------------------------------------------- |
| AgentEvent          | 标准化的事件单元，所有分析器的统一输入                                            |
| AgentUICommand      | 统一的 UI 指令，所有分析器的统一输出                                              |
| SignalQueue         | 信号队列，负责指令的冷却/去重/排序/分发                                           |
| CooldownTracker     | 冷却追踪器，避免同类提示反复打扰                                                  |
| CanvasAgent         | 画布 Agent 交互 Hook，封装连接建议/空白区/共识                                    |
| MoodDetector        | 情绪检测器，基于近 1 分钟事件推断写作情绪                                         |
| ConsensusDetector   | 共识检测器，基于 Embedding 相似度聚类观点                                         |
| SemanticGapDetector | 语义空白区检测器，识别画布缺失的讨论视角                                          |
| HandoffTracker      | 接力追踪器，检测多人协作的编辑权交接                                              |
| WritingProfile      | 写作画像，跨文档聚合的写作习惯统计                                                |
| WritingReport       | 写作复盘报告，LLM 生成的中性叙事报告                                              |
| ReplayMarker        | 回放标记，时间轴上的关键帧标注                                                    |
| ChatDistill         | 聊天蒸馏，将聊天消息沉淀为画布节点                                                |
| CanvasContext       | 画布上下文，为 CoWrite Prompt 注入画布信息                                        |
| flush               | 信号队列的批量分发操作                                                            |
| dispatch            | 入队并立即分发单条指令                                                            |
| dismiss             | 忽略 Agent 建议，同类不再提示                                                     |
| degradable          | 可降级，无 AI 时规则仍可用                                                        |
| ReplayMarkerType    | flow（流畅）/ stuck（停顿）/ handoff（接力）/ consensus（共识）/ conflict（分歧） |
| FloralMood          | happy / neutral / sleepy / excited / worried / curious                            |
| InsightRouter       | Rust 端洞察路由器，分发到 UI/Live2D/回放/复盘                                     |
