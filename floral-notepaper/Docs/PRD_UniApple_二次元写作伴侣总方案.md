# PRD · 花溯 二次元桌面写作伴侣总方案

> 版本：v1.0  
> 日期：2026-06-26  
> 定位：面向写作过程的、有人情味的二次元桌面创作空间  

---

## 1. 一句话定位

**花溯 是一款面向写作过程的二次元桌面写作伴侣：用户可以在无限画布中组织文档，用墨迹回放看见自己的写作过程，并通过 Live2D 虚拟角色与声音系统获得长期陪伴。**

花溯 不只是编辑器，也不只是桌宠或聊天软件。它的核心是：

```text
文档空间 + 写作过程 + Live2D 陪伴 + 声音人格 + Agent 洞察
```

最终体验应该是：

> 用户不是一个人在冷冰冰的工具里写作，而是在一个有角色、有回忆、有空间关系、有复盘能力的创作世界里完成长期写作。

---

## 2. 核心竞争力

| 方向 | 核心差异化 | 产品价值 |
| --- | --- | --- |
| 无限画布文档空间 | 文档不是列表里的文件，而是画布中的空间对象 | 让用户用空间方式组织思考、项目和资料 |
| Live2D 写作陪伴 | 二次元角色以动作和 presence 陪伴写作 | 让编辑器从工具变成同伴 |
| 角色声线工坊 | 用户可训练/绑定自己的角色声音 | 让 TTS 从功能配置升级为角色人格资产 |
| 墨迹回放 Agent | 回放并分析写作过程，而不只看最终文本 | 帮用户看见自己如何写作 |
| 多人协作 presence | 每个用户以角色形象参与协作 | 让多人编辑更有在场感和情绪连接 |
| Rust Agent 引擎 | 高性能处理事件流、画布关系和写作轨迹 | 形成桌面端技术护城河 |

## 4. 方向一：无限画布文档空间 PRD

### 4.1 功能定位

无限画布不是普通白板，而是**文档、文件夹、项目和角色关系的空间化容器**。

当前问题：文档拖入画布后只显示标题，不能打开内容、预览内容、建立关系或触发进一步操作。  
目标：把画布里的文档升级为 **Document Node：文档在无限画布中的空间投影**。

---

### 4.2 设计方向：2 + 3 混合

用户已确认采用：

```text
视觉手账型 + 空间知识节点型
```

也就是：

- 外观像纸张、便签、文件夹、手账卡片，有温度和二次元氛围。
- 底层是可连接、可聚合、可被 Agent 理解的知识节点。

这不是 Notion 页面，也不是普通白板贴纸，而是：

> 一个既有视觉情绪，又有结构语义的文档空间对象。

---

### 4.3 文档节点三层形态

| 状态 | 展示内容 | 作用 |
| --- | --- | --- |
| 折叠态 | 标题、类型图标、更新时间、角色印章、连接点 | 快速组织与拖拽布局 |
| 预览态 | 标题、3-5 行内容预览、大纲、最近修改、操作按钮 | 不离开画布快速理解内容 |
| 打开态 | 右侧抽屉或中央编辑器打开完整文档 | 阅读、编辑、协作、评论 |

#### 折叠态

适合大量文档在画布上组织：

```text
┌────────────────────┐
│ 📄 PRD 草稿         │
│ 06-26 更新 · 812字  │
│ 🌸 梅陪写过         │
└────────────────────┘
```

#### 预览态

适合快速查看内容：

```text
┌────────────────────────────┐
│ 📄 PRD 草稿                 │
│ 这篇主要讨论 Live2D 与 TTS...│
│ · 1. 产品定位               │
│ · 2. 声音工坊               │
│ · 3. 画布节点               │
│ [打开] [摘要] [连线] [协作] │
└────────────────────────────┘
```

#### 打开态

适合完整操作：

- 双击节点：在右侧抽屉打开。
- Alt + 双击：在中央主编辑器打开。
- 协作模式下：打开多人编辑状态。

---

### 4.4 文档节点操作

| 操作 | 结果 |
| --- | --- |
| 单击 | 选中文档节点 |
| 双击 | 打开文档详情 |
| 悬停 | 显示轻量预览 |
| 右键 | 打开菜单：打开、预览、复制引用、加入协作、生成摘要 |
| 拖拽边缘连接点 | 与其他文档建立关系 |
| 框选多个节点 | 组成文档组/项目组 |
| 拖入文件夹区域 | 归入文件夹房间 |
| 点击角色印章 | 查看该角色与文档的陪伴关系 |

---

### 4.5 文件夹房间 Folder Room

文件夹在画布中不应只是目录，而应该是一个**可进入的项目房间**。

| 文件夹状态 | 画布表达 |
| --- | --- |
| 普通文件夹 | 一个可展开的文件夹卡片 |
| 项目文件夹 | 有边界区域的项目房间 |
| 长期活跃文件夹 | 显示角色驻留/项目花圃 |
| 已完成合集 | 显示完成纪念物 |
| 静养书架 | 安静沉淀，不枯萎、不惩罚 |

文件夹房间可以承载：

- 多个文档节点。
- 文件夹级 Live2D 陪伴痕迹。
- 项目阶段。
- 画布区域备注。
- 团队协作 presence。

---

### 4.6 画布 Agent 能力

画布 Agent 不直接替用户写内容，而是理解空间关系：

| 能力 | 输出 |
| --- | --- |
| 隐含连接 | “这两个文档可能在讨论同一个问题，要不要连起来？” |
| 空间聚类 | 自动识别某一区域是一组项目文档 |
| 缺口提醒 | “这里有问题分析和解决方案，但缺少可行性评估。” |
| 发散/收敛判断 | “当前新增节点很多，可能还在发散期。” |
| 成熟度判断 | “这个区域连接较完整，可以收拢成项目组。” |
| 冗余检测 | “这两张卡片内容可能重复。” |

### 4.7 MVP 范围

Must：

- 拖入文档生成 Document Node，而不是普通矩形标题。
- 节点显示标题、更新时间、字数/预览、类型图标。
- 双击打开文档。
- 右键菜单。
- 节点保留 `docId`，与原文档双向关联。
- 支持节点连接。

Should：

- 悬停预览。
- 角色陪伴印章。
- 多节点分组。
- AI 摘要卡。

Won't for MVP：

- 自动全文理解所有文档。
- 大规模知识图谱自动生成。
- 复杂 3D 画布。
- 画布中直接嵌完整编辑器。

---

## 5. 方向二：Live2D 双模式写作陪伴 PRD

### 5.1 功能定位

Live2D 是 UniApple 的情绪入口。它既不是纯装饰，也不是 AI 聊天窗口，而是用户在写作空间中的长期陪伴存在。

用户确认采用：

```text
双模式切换
```

---

### 5.2 双模式定义

| 模式 | 名称 | 是否说话 | 默认场景 | 目标 |
| --- | --- | --- | --- | --- |
| 陪伴模式 | 写作陪伴小人 | 默认不说话 | 编辑器、画布、回放 | 安静陪伴，不打扰 |
| 人格模式 | Elysia 角色人格 | 可以说话 | TTS、聊天、语音房 | 二次元互动、朗读、对话 |

核心边界：

> 写作时它陪你；你主动唤起时，它才开口。

---

### 5.3 陪伴模式

陪伴模式只根据非正文事件行动：

| 事件 | 角色行为 |
| --- | --- |
| 打开文档 | 待机、呼吸、眨眼 |
| 开始输入 | 抬头、看向编辑区 |
| 连续输入 | 低频点头或陪坐 |
| 停顿 | 托腮、等待 |
| 大量删除 | 安静陪伴，不责备 |
| 保存成功 | 轻微安心动作 |
| 发布/完成 | 低幅庆祝 |
| 长 session | 自动降噪 |
| 用户关闭 | 立即隐藏，不挽留 |

禁止：

- 写作中主动说话。
- 评价正文。
- 读取正文内容。
- 催促用户继续写。
- 断更惩罚。
- 任务化签到。

---

### 5.4 人格模式

人格模式由用户主动打开：

入口：

- Elysia 页面。
- TTS 页面。
- 右侧 AI 聊天栏。
- 文档朗读按钮。
- 多人协作语音房。
- 角色详情页。

能力：

| 能力 | 说明 |
| --- | --- |
| 文档朗读 | 用角色声线朗读当前文档 |
| 主动问答 | 用户主动对角色提问 |
| 语音聊天 | STT + LLM + TTS |
| 情绪语音 | 根据用户选择或文本情绪使用不同参考音频 |
| 协作语音 | 多人协作时角色根据语音音量动嘴 |
| 角色口吻 | 可配置说话风格，但不进入正文输入链路 |

---

### 5.5 文章/文件夹/项目关系

Live2D 关系不是“角色读懂文章”，而是：

> 角色陪某个写作容器经历了创建、修改、完成、回访、归档和再生长。

| 层级 | 关系表达 |
| --- | --- |
| 文档 | 它陪我写完这篇 |
| 文件夹 | 它陪我长期做这个项目 |
| 项目空间 | 它陪我经营这片创作空间 |

允许记录：

- 陪伴 session 数。
- 完成次数。
- 回访次数。
- 最近陪伴角色。
- 完成纪念物。
- 文件夹活跃文档数。

不记录：

- 正文。
- 标题语义。
- 摘要。
- 主题。
- 内容质量。
- 用户情绪判断。

---

### 5.6 MVP 范围

Must：

- Live2D 配置页。
- 陪伴/人格双模式开关。
- P0 动作状态机。
- 用户可关闭/最小化。
- 文档完成后生成非正文陪伴记录。

Should：

- 角色选择。
- 动作收藏。
- 文件夹关系。
- 多人 presence 小人。

Won't for MVP：

- 复杂换装市场。
- 主动写作建议。
- 全自动剧情对话。
- 读取正文生成情绪台词。

## 6. 方向三：角色声线工坊 / GPT-SoVITS 产品化 PRD

### 6.1 功能定位

当前 GPT-SoVITS 配置页偏工程化。后续应升级为：

> **角色声线工坊：用户为自己的 Live2D 角色创建、训练、绑定和试听专属声音。**

用户感知不应该是“配置 TTS 参数”，而是：

> 我在创造一个有形象、有声音、有情绪表达的二次元写作搭子。

---

### 6.2 核心流程

```text
创建角色
-> 选择/导入 Live2D 模型
-> 上传声音样本
-> 标注情绪参考音频
-> 配置 GPT-SoVITS 模型
-> 试听角色说话
-> 应用到朗读/聊天/协作
```

---

### 6.3 产品概念映射

| 技术项 | 产品化名称 |
| --- | --- |
| GPT-SoVITS | 本地角色语音引擎 |
| `.ckpt` | GPT 声线理解核心 |
| `.pth` | SoVITS 声音生成核心 |
| API 地址 | 本地语音引擎连接 |
| 参考音频目录 | 情绪声线素材库 |
| wav 情绪标签 | 情绪声线卡 |
| 默认语速 | 说话节奏 |
| 模型加载 | 唤醒角色声音 |
| TTS 测试 | 让角色说一句话 |

---

### 6.4 情绪声线卡

用户可以为角色配置不同情绪的参考音频：

| 情绪 | 文件命名 | 用途 |
| --- | --- | --- |
| 平静 | `【平静】xxx.wav` | 默认朗读 |
| 开心 | `【开心】xxx.wav` | 完成、庆祝、轻松对话 |
| 认真 | `【认真】xxx.wav` | 读 PRD、读技术文档 |
| 温柔 | `【温柔】xxx.wav` | 陪伴、安慰、复盘 |
| 生气 | `【生气】xxx.wav` | 可选，不建议默认启用 |
| 难过 | `【难过】xxx.wav` | 可选，谨慎使用 |

默认策略：

- 正文朗读优先平静/认真。
- 聊天可以使用开心/温柔。
- 写作中不自动播放语音。
- 用户主动触发时才发声。

---

### 6.5 角色声音资产

```ts
interface VoiceProfile {
  id: string;
  characterId: string;
  engine: 'gpt-sovits' | 'edge-tts' | 'openai-tts' | 'system';
  apiUrl: string;
  gptWeightsPath?: string;
  sovitsWeightsPath?: string;
  refAudioDir?: string;
  emotionSamples: EmotionVoiceSample[];
  defaultSpeed: number;
  defaultEmotion: string;
  enabledScenes: VoiceScene[];
}
```

```ts
type VoiceScene =
  | 'document_reading'
  | 'active_chat'
  | 'replay_review'
  | 'collab_voice'
  | 'character_preview';
```

---

### 6.6 MVP 范围

Must：

- 保留现有 GPT-SoVITS 配置。
- 增加“试听一句话”。
- 增加“加载模型”按钮。
- 增加情绪参考音频列表。
- 绑定 voice profile 到角色。
- 支持当前文档朗读。

Should：

- 情绪样本自动扫描。
- 角色声音预设。
- 朗读历史缓存。
- 多角色声线切换。

Won't for MVP：

- 在线训练完整模型。
- 声音市场。
- 复杂音频剪辑器。
- 自动克隆他人声音。

---

### 6.7 合规与边界

- 必须提示用户只上传自己有权使用的声音。
- 禁止默认提供真人明星/公众人物声音克隆。
- 角色声线应偏原创虚拟角色。
- 导出或分享 voice profile 时应带版权声明。
- 多人协作中使用语音前应有用户授权。

## 7. 方向四：墨迹回放 Agent PRD

### 7.1 功能定位

墨迹回放不是简单录屏，而是记录写作行为的时间序列：

- 光标移动。
- 输入。
- 删除。
- 选中。
- 跳转。
- 粘贴。
- 停顿。
- 保存。
- 完成。

Agent 要从这些痕迹中读懂用户的写作过程。

> 普通写作工具帮你把字写出来；墨迹回放 Agent 帮你看见自己是怎么写出来的。

---

### 7.2 核心能力

| 能力 | 分析内容 | 输出 |
| --- | --- | --- |
| 高频修改区 | 哪些句子/段落反复删改 | 修改热点 |
| 流畅度曲线 | 单位时间有效输出变化 | 流畅期/卡顿期 |
| 停顿点分析 | 停顿时长、位置、前后操作 | 卡住的位置 |
| 删除模式 | 删除字、句、段，重写差异 | 是改内容还是改表达 |
| 思路转折点 | 写完某处后跳到另一处 | 发现思路跳跃 |
| 灵光闪现 | 短时间高输出且少修改 | 高光片段 |
| 写作习惯 | 长期 session 模式 | 个性化建议 |

---

### 7.3 回放时间轴标注

回放进度条应自动生成标记点：

| 标记 | 颜色/类型 | 含义 |
| --- | --- | --- |
| 高光 | 金色 | 高速输出且少改 |
| 卡顿 | 蓝色 | 长停顿/反复移动 |
| 重写 | 红色 | 大段删除后重写 |
| 转折 | 紫色 | 跳转到新结构位置 |
| 完成 | 绿色 | 保存/发布/标记完成 |

点击标记后可看到：

```text
这里你停了 2 分 18 秒，然后删掉了上一句，重新写了一个更明确的结论。
```

注意：输出应温柔、观察式，不评价好坏。

---

### 7.4 Agent 输出风格

允许：

- “这里似乎是一个思路转折点。”
- “你在这一段停留了比较久。”
- “这段是一气呵成写出来的。”
- “你可能在调整表达，而不是改变观点。”

禁止：

- “你写得不好。”
- “你应该这样写。”
- “你很焦虑。”
- “这篇质量很差。”
- 强制改写正文。

---

### 7.5 MVP 范围

Must：

- 记录操作事件流。
- 回放时间轴。
- 修改热点。
- 停顿点。
- 流畅区。
- 大量删除区。
- 生成一次写作复盘报告。

Should：

- 对比历史最佳写作 session。
- Live2D 陪用户看回放。
- 复盘报告导出。

Won't for MVP：

- 自动评价文章质量。
- 自动改写全文。
- 情绪诊断。
- 复杂心理分析。

---

## 8. 方向五：多人协作与角色 presence PRD

### 8.1 功能定位

多人协作不只是多人同时编辑，更应该让用户感到：

> 我不是和一个冷冰冰的头像一起写，而是和对方的角色一起在这个空间里工作。

---

### 8.2 核心场景

| 场景 | 体验 |
| --- | --- |
| 好友进入文档 | 右侧栏出现好友 Live2D presence |
| 好友正在写 | 对方小人进入书写状态 |
| 好友发消息 | 小人旁边出现气泡 |
| 语音通话 | 小人根据音量张嘴/眨眼 |
| 同时编辑同一区域 | 轻量提示，不直接打断 |
| 共同完成文档 | 多人小人一起低幅庆祝 |

---

### 8.3 协作布局

```text
┌──────────┬────────────────────────┬──────────────────┐
│ 左导航    │ 中央文档/无限画布        │ 右侧协作栏         │
│          │                        │ 好友消息          │
│          │ 文档节点 / 编辑器        │ 角色 presence     │
│          │                        │ 语音通话          │
└──────────┴────────────────────────┴──────────────────┘
```

右侧栏承担：

- 聊天。
- 在线成员。
- 语音通话。
- 好友 Live2D 小人。
- 协作日志。

中央区域保持专业，不让小人大面积遮挡正文或节点。

### 8.4 权限策略

| 行为 | 默认 | 是否可关闭 |
| --- | --- | --- |
| 在线 presence | 开启 | 可隐藏 |
| 正在编辑状态 | 开启 | 可隐藏 |

| 挥手/击掌 | 低频开启 | 可屏蔽 |

## 9. 方向六：Agent 引擎 PRD

### 9.1 功能定位

Agent 是 UniApple 的“理解层”，负责处理开放性、分支不可枚举的写作场景。

它不是单一聊天机器人，而是多个专业 Agent 的组合：

| Agent | 负责 |
| --- | --- |
| 墨迹回放 Agent | 理解写作过程 |
| 画布理解 Agent | 理解空间关系 |
| 陪伴调度 Agent | 决定 Live2D 何时动、何时安静 |
| 声音人格 Agent | 处理主动聊天和语音表达 |
| 协作洞察 Agent | 理解多人协作动态 |

---

### 9.2 为什么用 Rust

| 挑战 | Rust 价值 |
| --- | --- |
| 多人实时协作 | 高并发、低延迟、内存安全 |
| 画布大量事件 | 高性能事件流处理 |
| 墨迹回放数据量大 | 本地压缩、索引、分析 |
| 桌面端隐私 | 本地优先处理敏感事件 |
| Tauri 集成 | Rust 原生后端与前端壳分工清晰 |

---

### 9.3 Agent 分层

```text
事件采集层
-> 本地聚合层
-> Rust Agent Engine
-> LLM / 本地规则 / 向量检索
-> UI 提示 / Live2D 动作 / 回放标注
```

原则：

- 高频输入事件先本地聚合。
- 不把所有原始正文发给远端。
- 写作中不阻塞输入链路。
- Agent 输出必须可关闭。
- 建议要温和，不要命令式。

---

### 9.4 MVP 切入点

推荐优先做：

```text
墨迹回放 Agent -> 写作洞察
```

原因：

- 数据结构稳定。
- 用户价值直观。
- 不需要先解决复杂画布语义。
- 很符合“写作伴侣”的独特定位。

后续再做：

```text
画布理解 Agent -> 协作 Agent -> 陪伴调度 Agent 增强
```

## 10. 方向七：商业化与创作者生态 PRD

### 10.1 商业化原则

基础陪伴不能收费，收费点应该是更多表达和个性化。

免费必须有：

- 基础 Live2D 陪伴。
- 基础文档节点。
- 基础 TTS/系统语音。
- 基础陪伴关系。
- 基础墨迹回放。

会员可以有：

- 更多角色。
- 更多动作。
- 更多服装。
- 更多声音槽位。
- 更多情绪声线卡。
- 更多回忆展示样式。
- 多设备同步。
- 高级画布主题。
- 高级 Agent 复盘报告。

禁止：

- 免费用户没有基础陪伴。
- 免费用户关系记录过期。
- 会员成长更快。
- 付费解除断更惩罚。
- 写作中强推会员弹窗。

---

### 10.2 创作者市场

P4 可开放：

- Live2D 模型市场。
- 动作包市场。
- 服装市场。
- 主题房间市场。
- 声音预设市场。
- 画布卡片皮肤市场。

但需要前置治理：

- 版权审核。
- 性能标准。
- 模型大小限制。
- 角色内容规范。
- 声音授权声明。
- 安全导入沙箱。

## 11. 路线图

### Phase 1：画布文档节点 MVP

### Phase 2：角色声线工坊 MVP

目标：把 GPT-SoVITS 配置变成可用的二次元角色声音系统。

交付：

- 加载模型。
- 试听一句话。
- 情绪音频样本列表。
- 当前文档朗读。
- 角色绑定 voice profile。

---

目标：实现“陪伴模式 + 人格模式”。

交付：

目标：让协作变得有人在场。

交付：

## 12. 当前最应该先做什么

推荐优先级：

1. **画布 Document Node**：解决当前产品最直观的问题，立刻提升创新感。
2. **TTS 试听与模型加载**：让 Elysia 配置页从静态 UI 变成可用功能。
3. **Live2D 双模式开关**：先确立产品边界。
4. **墨迹回放 Agent 基础洞察**：形成真正技术差异化。
5. **多人角色 presence**：在协作基础稳定后做。

## 13. 最终产品判断

如果只做画布，UniApple 像白板。  
如果只做 TTS，UniApple 像语音助手。  
如果只做 Live2D，UniApple 像桌宠。  
如果只做 Agent，UniApple 像普通 AI 写作工具。  

真正有差异化的是组合：

> **一个能把文档放进空间、让角色陪你写作、用声音和你交流、并能回放理解你创作过程的二次元桌面写作伴侣。**

这就是 UniApple 的核心壁垒。
