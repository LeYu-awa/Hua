# 方案 · 产品战略（留存主线：写作日记流 + 订阅制变现）

日期：2026-08-09
项目：floral-notepaper
状态：战略已确认，待实施
关联文档（支撑层）：`2026-08-09-live2d-writing-coach-design.md`、`2026-08-09-canvas-product-design.md`、`2026-08-09-rust-orchestrator-agent-design.md`

## 1. 战略结论

**留存主线 = 写作日记流**：用户每天和 Live2D 角色对话（语音/文字），内容自动沉淀为日记/随记，角色持续"记得"，每周主动复盘。**组卡成文从主线降为副产品**（月度回忆录的触发点）。

**变现路径 = 订阅制**：基础写作免费，订阅解锁 AI/语音/复盘/同步等高级能力。

产品一句话：

> **一个会记得你写作与生活的数字伴侣——你每天和它说话，它替你沉淀、复盘、陪你把生活聊成文字。**

## 2. 为什么是日记流（留存逻辑）

| 一次性魔法（原设计） | 留存引擎（日记流） |
|---|---|
| 组卡成文：用完即弃 | 每日对话：明天还要回来 |
| 无资产积累 | 每一天的记录都在沉淀，"人生记录"越来越重，换平台成本高 |
| 可被 ChatGPT 替代 | "角色记得你月初的烦恼"——不可替代的关系记忆 |
| 低频（框选才触发） | 高频（每天 5 分钟） |

## 3. 用户旅程（每日循环）

```
早上/睡前：用户和角色说几句当天的事（语音或文字）
  → 角色引导型提问（"今天有什么事印象深刻？"）
  → 对话自动沉淀为日记条目（画布时间线 / 日记列表自动生长）
  → 角色更新记忆（profile_store + embedding）
  → 次日继续
每周日：角色主动复盘（review.report）：
  "这周你写了 5 篇随记、卡壳 2 次、有 1 个灵感没展开——要不要聊聊？"
每月：攒够一个月的记录 → 角色提议"写一篇月度回忆录？"
  → 组卡成文（canvas.read → llm.generate → note.create）← 组卡成文在这里复活
```

### 3.1 闭环钩子

- **日钩子**：角色主动问候/提问（Live2D 主动信号，规则引擎已有）——每天一个轻量动作
- **周钩子**：复盘报告揭示"你没意识到的自己"（写作模式/卡壳周期）
- **月钩子**：回忆录让一个月的碎片变成一篇可读的东西
- **记忆钩子**：角色能引用你上周的话（"你上周说过想写这个"）——**这是杀手锏**

## 4. 核心机制（依赖已有零件）

| 机制 | 说明 | 已有能力 |
|---|---|---|
| 事件采集 | 写作/对话/状态全记录 | `event_store` ✅ |
| 记忆 | 角色记得用户偏好与经历 | `profile_store` + `embedding_service` ✅（待接入对话） |
| 周复盘 | 每周生成结构化报告 | `agent_generate_review_report` ✅ |
| 回放 | 重放某天的写作过程 | `replay_marker` ✅ |
| 沉淀 | 对话 → 日记条目 | 新增（画布/日记数据结构） |
| 记忆引用 | 角色在对话中引用过去 | 新增（接 embedding 检索） |

## 5. 免费 / 订阅分层

| 能力 | 免费 | 订阅 |
|---|---|---|
| 基础写作 + 本地笔记/画布 | ✅ | ✅ |
| 每日 AI 对话 | 限量（如 20 条/天） | 无限 |
| 角色语音（TTS） | 限量（如 10 条/天） | 无限 |
| 周复盘报告 | ❌（显示 7 天摘要） | ✅ 完整 |
| 月度回忆录 | ❌ | ✅ |
| 云同步 | ❌ | ✅ |
| 高级统计/成长曲线 | ❌ | ✅ |

付费诱饵：**月度回忆录 + 周复盘**（数据产品，非对话可比），订阅是"买回自己的数据价值"。

## 6. 关键指标

- **D1/D7 留存**：次日回来的比例（日钩子的效果）
- **对话深度**：每日对话轮数 / 时长（语音 TTS 的使用）
- **沉淀量**：日记条目数（资产积累的代理指标）
- **周复盘打开率**（周钩子效果）
- **付费转化**：月回忆录生成数 / 订阅转换

## 7. 对既有方案的影响

| 文档 | 调整 |
|---|---|
| 写作导师方案 | 引导型角色从"帮写文章"扩为"每天陪聊生活/想法"；收敛检测服务于"提议复盘/回忆录" |
| 画布产品设计 | 画布从"项目工作台"变为"日记流的时间线空间"；组卡成文保留但服务于回忆录 |
| Rust 编排架构 | 主线任务的典型场景 = 每日对话沉淀 + 周复盘 + 回忆录；工具集增加"日记沉淀"产出 |

## 8. 实施优先级（按留存价值）

| 阶段 | 内容 | 留存价值 |
|---|---|---|
| S1 | 每日对话 → 自动沉淀日记条目（画布时间线） | ★★★ 日钩子 |
| S2 | 角色主动问候 + 记忆引用（接 embedding/profile） | ★★★ 记忆钩子 |
| S3 | 周复盘报告（review.report 接 UI + 语音播报） | ★★ 周钩子 |
| S4 | 月度回忆录（组卡成文复用） | ★★ 月钩子 + 付费诱饵 |
| S5 | 订阅分层落地（用量限制 + 云同步） | 变现 |

## 9. 风险与注意事项

1. **对话疲劳**：每日对话不能变成负担——角色提问要有质量（引导型），允许"今天没话说"（记录"无内容"也算沉淀）。
2. **记忆不能错**：角色引用过去必须准确（只引用 embedding 检索到的高相关片段），错记一次信任就崩。
3. **隐私敏感**：日记是私密数据，本地优先（Tauri 本地存储天然优势），云同步做可选项。
4. **复盘别唠叨**：周复盘要"洞察"而非"汇总"，否则变成骚扰。
5. **免费额度别砍体验**：免费层必须能完整体验"沉淀"（写日记），付费才解锁"数据产品"。
