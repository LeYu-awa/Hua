# 方案 · 画布产品设计（灵感花园 + 文章类产出）

日期：2026-08-09
项目：floral-notepaper
状态：产品定位已确认，待实施
关联文档：`2026-08-09-live2d-writing-coach-design.md`（产品定位）、`2026-08-09-rust-orchestrator-agent-design.md`（技术架构）

## 1. 产品定位（已确认）

**画布 = 灵感花园**（想法收集/组织/推演的空间），**产出型工具 = 文章**。

- 画布核心定位：**灵感组织为主**——收集想法、组织卡片、找空白、最终一键整理成文。
- 产出型工具优先级：**文章类产出**——`note.generate`（大纲/初稿/摘要）+ 组卡成文。

产品主线：

```
散想法 → 灵感花园（画布）→ 组卡成文 → 新文章（note）
   ↑          ↑ 分组/连线/Agent补想法       ↑ 角色提议/语音
   └── Live2D 角色在花园里陪着你，把想法聊成文章
```

## 2. 画布功能设计

### 2.1 功能总览

| 类别 | 功能 | 状态 |
|---|---|---|
| 收集 | 四类节点（text/card/resource/task）、拖动/连线/编辑/保存 | ✅ 已有 |
| 组织 | **分组/泳道**（按主题/章节） | ❌ 新增 |
| 组织 | **resource 节点可打开对应笔记** | ❌ 新增 |
| 推演 | Agent 隐含连接（dashed 边）、语义空白区、共识分歧 | ✅ 已有 |
| 沉淀 | 聊天沉淀到画布（决策/待办/风险） | ✅ 已有 |
| 产出 | **组卡成文入口**（选中 → 角色提议 → 成文） | ❌ 新增 |
| 产出 | **已成文卡片留痕标注**（可回看产出过程） | ❌ 新增 |
| 表演 | **Live2D 在画布指引/气泡** | ❌ 新增 |

### 2.2 新增功能详述

**① 分组/泳道**
- 节点可归属一个分组（组名 + 颜色 + 泳道区域）。
- 交互：拖节点到分组/新建分组；分组支持折叠/展开。
- 用途：按主题（"人物" / "情节" / "素材"）、章节、或想法成熟度分组。
- 数据：`CanvasNode.group: string | null`；分组定义存画布文档。

**② resource 节点打开对应笔记**
- `resource` 节点携带 `note_id` 时，双击/悬停可打开对应笔记。
- 反向：笔记列表可"拖到画布"生成 resource 节点（画布 ↔ 笔记双向）。

**③ 组卡成文入口**
- 交互 A：框选一组卡片 → 工具栏出现"整理成文"按钮。
- 交互 B（角色主动）：组卡达到"成文收敛"信号时，角色提议（见 §4）。
- 触发后进入核心流程（§4）。

**④ 已成文留痕标注**
- 参与成文的卡片打标 `drafted: task_id`，样式弱化 + 链接标识。
- 点击标注可回看：任务记录（哪些卡片 → 产出了哪篇文章）。
- 数据：`CanvasNode.drafted_by: string | null`（task_id）。

**⑤ Live2D 表演空间**
- Agent 输出经输出总线 → `live2d_signal_queue`：角色在画布上表达（情绪/气泡指向节点）。
- 场景：提议成文（curious）、执行中（thinking）、完成（excited + 语音朗读开头）。

## 3. 产出型工具设计（文章类优先）

### 3.1 工具清单

| 工具 | 产出 | 落点 | 优先级 |
|---|---|---|---|
| `note.generate` | 大纲 / 初稿 / 摘要 / 改写 | 新笔记 | P0 |
| `canvas_to_note`（组卡成文） | 由一组画布卡片生成文章 | 新笔记 | P0 |
| `review.report` | 复盘/写作报告 | 文档/面板 | P1 |
| `replay.marker` | 写作过程标记 | 回放库（已有） | P1 |
| `speech.speak` | 语音播报（表达通道） | Live2D+TTS | P1 |

### 3.2 组卡成文 = 组合型工具

```
canvas.read（读选中卡片，含分组/连线关系）
  → llm.generate（LLM 组织成文：标题 + Markdown 正文）
  → note.create（新笔记）
```

- 输入：选中卡片集 + 可选用户意图（"写成小说开篇" / "整理成总结"）。
- 输出：文章草稿（预览）。

### 3.3 预览-确认-落盘（产品铁律）

- 所有文章类产出**先预览、用户确认后才落盘**（复用现有写回审查体验）。
- 预览面板：标题可编辑 + 正文可编辑 + "重新生成" + "落为新笔记" / "取消"。
- 产出带 `source: "agent"` + `task_id`，可溯源。

### 3.4 溯源

- 新笔记记录 `provenance: { task_id, source_canvas: documentId, node_ids: [...] }`。
- 画布卡片标注 `drafted_by: task_id`。
- 笔记与画布互相可查：笔记 → 哪些卡片产出；卡片 → 产出的笔记。

## 4. 核心流程：组卡成文（端到端）

```
1. 用户框选卡片（或角色感知到收敛信号主动提议）
2. Live2D 角色提议：curious + 气泡 + 语音"这几张卡片够成一篇文章了"
3. 用户确认 → Rust 编排创建 Task（goal = 组卡成文，plan = canvas.read → llm.generate → note.create）
4. 执行中：面板显示进度；角色 thinking 动画
5. 产出预览：侧栏显示标题+正文（可编辑/重新生成）
6. 用户确认 → note.create 落成新笔记
7. 完成：角色 excited + 语音朗读开头；卡片打 drafted 标注
8. 回看：任务记录可追溯"哪些卡片 → 哪篇文章"
```

### 收敛信号（角色何时主动提议）

- 规则：选中/相关卡片 ≥3 张，且主题词重复（可借鉴写作导师方案 §4.2 收敛检测）。
- 防打扰：同主题只提议一次 + 冷却。

## 5. Live2D 参与点

| 阶段 | 角色表现 |
|---|---|
| 提议成文 | curious / thinking，气泡指向卡片组 |
| 执行中 | thinking 动画 + 轻声播报进度 |
| 产出预览 | 等待用户确认（不抢戏） |
| 落盘成功 | excited + 语音朗读开头 |
| 用户拒绝 | 无所谓 / 换一种写法再提议 |

## 6. 与现有体系的关系

| 文档 | 关系 |
|---|---|
| 写作导师方案 | 本设计的"组卡成文/角色提议"是写作导师的产出落点；两者共享收敛检测 |
| Rust 编排架构 | 画布功能（分组/标注）是画布数据模型扩展；组卡成文是组合型工具 + 输出总线到 Live2D/语音 |

## 7. 实施阶段与改动点

| 阶段 | 内容 | 主要改动 |
|---|---|---|
| P0-1 | 画布分组/泳道 + resource 打开笔记 | `CanvasNode` 加 `group`；`CanvasPage` 交互 |
| P0-2 | 组卡成文（先按钮触发）：`canvas.read → llm.generate → 预览 → note.create` | 新增组合工具 + 预览面板；Rust `canvas_to_note` |
| P0-3 | 角色提议 + 收敛信号 + Live2D/语音参与 | 复用写作导师收敛检测；输出总线接 Live2D + TTS |
| P1 | 已成文留痕/回看 + 溯源字段 | `drafted_by` / `provenance`；任务记录查询 |
| P1 | `review.report` / `replay.marker` | 复用 Rust 已有命令 |

## 8. 风险与注意事项

1. **预览确认不省略**：文章类产出一律先预览后落盘，避免 Agent 擅自生成。
2. **收敛提议防打扰**：冷却 + 去重，避免角色反复提议。
3. **卡片组过大**：>N 张卡片时提示分批或自动精简素材（按主题聚簇）。
4. **画布模型兼容**：`group` / `drafted_by` 为增量字段，旧画布文档默认 null，不破坏现有读取。
5. **LLM 依赖**：组卡成文依赖供应商配置；未配置时入口置灰并提示。
