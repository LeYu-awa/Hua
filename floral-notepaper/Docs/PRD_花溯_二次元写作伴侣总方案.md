# PRD · 花溯 二次元桌面写作伴侣总方案

> 版本：v2.0  
> 日期：2026-06-26  
> 产品名：花溯  
> 定位：面向写作过程的、有人情味的二次元桌面创作空间

---

## 1. 一句话定位

**花溯是一款面向写作过程的二次元桌面写作伴侣：用户可以在多人无限画布中组织文档，用墨迹回放看见自己的写作过程，并通过 Live2D 虚拟角色、声音系统和 Rust Agent 获得长期陪伴与写作洞察。**

花溯不只是编辑器，也不只是桌宠、白板或 AI 聊天软件。它的核心是：

```text
文档空间 + 写作过程 + Live2D 陪伴 + 声音人格 + Rust Agent 洞察
```

最终体验应该是：

> 用户不是一个人在冷冰冰的工具里写作，而是在一个有角色、有回忆、有空间关系、有复盘能力的创作世界里完成长期写作。

## 4. 产品闭环

花溯的关键不是把多个功能堆在一起，而是让它们互相咬合，形成一个写作伴侣闭环。

```text
用户写作（Live2D 陪伴）
        ↓
墨迹回放记录操作过程
        ↓
Agent 分析写作行为（停顿、修改、流畅度、转折点）
        ↓
┌───────┴────────┐
↓                ↓
画布协作分析      养成系统反馈
多人模式下        个人模式下
↓                ↓
Agent 整合长期数据
        ↓
更懂你的 Live2D + 更精准的主动干预
        ↓
用户继续写作
```

### 4.1 关键联动场景

| 联动场景               | 说明                                                             |
| ---------------------- | ---------------------------------------------------------------- |
| 画布协作 → 回放分析    | 多人协作结束后，Agent 自动生成协作回放，标注共识、分歧和角色分工 |
| 回放分析 → 养成成长    | 每次写作诊断完成后，Live2D 增加陪伴经验，解锁动作、表情或回忆    |
| 养成状态 → 协作表现    | 多人协作时，每个人的写作风格档案可作为协作建议依据               |
| 协作数据 → 个人档案    | 用户在团队中的角色、贡献方式和协作习惯进入个人写作档案           |
| 画布关系 → Agent 提示  | 文档节点之间的空间/语义关系触发隐含连接、聚类和缺口建议          |
| 声音系统 → Live2D 人格 | 角色声线与 Live2D 形象绑定，形成可聊天、可朗读的二次元人格       |

## 5. 方向一：无限画布文档空间 PRD

### 5.1 功能定位

无限画布不是普通白板，而是**文档、文件夹、项目和角色关系的空间化容器**。

当前问题：文档拖入画布后只显示标题，不能打开内容、预览内容、建立关系或触发进一步操作。  
目标：把画布里的文档升级为 **Document Node：文档在无限画布中的空间投影**。

---

### 5.2 设计方向：视觉手账型 + 空间知识节点型

用户已确认采用 2 + 3 混合方案：

```text
视觉手账型 + 空间知识节点型
```

也就是：

- 外观像纸张、便签、文件夹、手账卡片，有温度和二次元氛围。
- 底层是可连接、可聚合、可被 Agent 理解的知识节点。

这不是 Notion 页面，也不是普通白板贴纸，而是：

> 一个既有视觉情绪，又有结构语义的文档空间对象。

---

### 5.3 文档节点三层形态

| 状态   | 展示内容                                       | 作用                   |
| ------ | ---------------------------------------------- | ---------------------- |
| 折叠态 | 标题、类型图标、更新时间、角色印章、连接点     | 快速组织与拖拽布局     |
| 预览态 | 标题、3-5 行内容预览、大纲、最近修改、操作按钮 | 不离开画布快速理解内容 |
| 打开态 | 右侧抽屉或中央编辑器打开完整文档               | 阅读、编辑、协作、评论 |

#### 折叠态

```text
┌────────────────────┐
│ 📄 PRD 草稿         │
│ 06-26 更新 · 812字  │
│ 🌸 梅陪写过         │
└────────────────────┘
```

#### 预览态

```text
┌────────────────────────────┐
│ 📄 PRD 草稿                 │
│ 这篇主要讨论 Live2D 与 TTS...│
│ · 1. 产品定位               │
│ · 2. 声音工坊               │
│ · 3. 画布节点               │
│ [打开] [摘要] [连线] [协作] │
└────────────────────────────┘
```

#### 打开态

- 双击节点：在右侧抽屉打开。
- Alt + 双击：在中央主编辑器打开。
- 协作模式下：打开多人编辑状态。

---

### 5.4 文档节点操作

| 操作           | 结果                                               |
| -------------- | -------------------------------------------------- |
| 单击           | 选中文档节点                                       |
| 双击           | 打开文档详情                                       |
| 悬停           | 显示轻量预览                                       |
| 右键           | 打开菜单：打开、预览、复制引用、加入协作、生成摘要 |
| 拖拽边缘连接点 | 与其他文档建立关系                                 |
| 框选多个节点   | 组成文档组/项目组                                  |
| 拖入文件夹区域 | 归入文件夹房间                                     |
| 点击角色印章   | 查看该角色与文档的陪伴关系                         |

---

### 5.5 文件夹房间 Folder Room

文件夹在画布中不应只是目录，而应该是一个**可进入的项目房间**。

| 文件夹状态     | 画布表达                 |
| -------------- | ------------------------ |
| 普通文件夹     | 一个可展开的文件夹卡片   |
| 项目文件夹     | 有边界区域的项目房间     |
| 长期活跃文件夹 | 显示角色驻留/项目花圃    |
| 已完成合集     | 显示完成纪念物           |
| 静养书架       | 安静沉淀，不枯萎、不惩罚 |

文件夹房间可以承载：

- 多个文档节点。
- 文件夹级 Live2D 陪伴痕迹。
- 项目阶段。
- 画布区域备注。
- 团队协作 presence。

---

### 5.6 画布 Agent 能力

画布 Agent 不直接替用户写内容，而是理解空间关系。

| 能力          | 输出                                             |
| ------------- | ------------------------------------------------ |
| 隐含连接      | “这两个文档可能在讨论同一个问题，要不要连起来？” |
| 空间聚类      | 自动识别某一区域是一组项目文档                   |
| 缺口提醒      | “这里有问题分析和解决方案，但缺少可行性评估。”   |
| 发散/收敛判断 | “当前新增节点很多，可能还在发散期。”             |
| 成熟度判断    | “这个区域连接较完整，可以收拢成项目组。”         |
| 冗余检测      | “这两张卡片内容可能重复。”                       |

### 5.7 MVP 范围

Must：

- 拖入文档生成 Document Node，而不是普通矩形标题。
- 节点显示标题、更新时间、字数/预览、类型图标。
- 双击打开文档。
- 右键菜单。
- 节点保留 `docId`，与原文档双向关联。
- 支持节点连接。

Should：

- 悬停预览。
- 角色陪伴印章。
- 多节点分组。
- AI 摘要卡。

Won't for MVP：

- 自动全文理解所有文档。
- 大规模知识图谱自动生成。
- 复杂 3D 画布。
- 画布中直接嵌完整编辑器。

## 6. 方向二：Live2D 双模式写作陪伴 PRD

### 6.1 功能定位

Live2D 是花溯的情绪入口。它既不是纯装饰，也不是 AI 聊天窗口，而是用户在写作空间中的长期陪伴存在。

用户确认采用：

```text
双模式切换
```

---

### 6.2 双模式定义

| 模式     | 名称            | 是否说话   | 默认场景           | 目标                   |
| -------- | --------------- | ---------- | ------------------ | ---------------------- |
| 陪伴模式 | 写作陪伴小人    | 默认不说话 | 编辑器、画布、回放 | 安静陪伴，不打扰       |
| 人格模式 | Elysia 角色人格 | 可以说话   | TTS、聊天、语音房  | 二次元互动、朗读、对话 |

核心边界：

> 写作时它陪你；你主动唤起时，它才开口。

---

### 6.3 陪伴模式

陪伴模式只根据非正文事件行动。

| 事件       | 角色行为         |
| ---------- | ---------------- |
| 打开文档   | 待机、呼吸、眨眼 |
| 开始输入   | 抬头、看向编辑区 |
| 连续输入   | 低频点头或陪坐   |
| 停顿       | 托腮、等待       |
| 大量删除   | 安静陪伴，不责备 |
| 保存成功   | 轻微安心动作     |
| 发布/完成  | 低幅庆祝         |
| 长 session | 自动降噪         |
| 用户关闭   | 立即隐藏，不挽留 |

禁止：

- 写作中主动说话。
- 评价正文。
- 读取正文内容。
- 催促用户继续写。
- 断更惩罚。
- 任务化签到。

---

### 6.4 人格模式

人格模式由用户主动打开。

入口：

- Elysia 页面。
- TTS 页面。
- 右侧 AI 聊天栏。
- 文档朗读按钮。
- 多人协作语音房。
- 角色详情页。

能力：

| 能力     | 说明                                   |
| -------- | -------------------------------------- |
| 文档朗读 | 用角色声线朗读当前文档                 |
| 主动问答 | 用户主动对角色提问                     |
| 语音聊天 | STT + LLM + TTS                        |
| 情绪语音 | 根据用户选择或文本情绪使用不同参考音频 |
| 协作语音 | 多人协作时角色根据语音音量动嘴         |
| 角色口吻 | 可配置说话风格，但不进入正文输入链路   |

---

### 6.5 文章/文件夹/项目关系

Live2D 关系不是“角色读懂文章”，而是：

> 角色陪某个写作容器经历了创建、修改、完成、回访、归档和再生长。

| 层级     | 关系表达               |
| -------- | ---------------------- |
| 文档     | 它陪我写完这篇         |
| 文件夹   | 它陪我长期做这个项目   |
| 项目空间 | 它陪我经营这片创作空间 |

允许记录：

- 陪伴 session 数。
- 完成次数。
- 回访次数。
- 最近陪伴角色。
- 完成纪念物。
- 文件夹活跃文档数。

不记录：

- 正文。
- 标题语义。
- 摘要。
- 主题。
- 内容质量。
- 用户情绪判断。

## 7. 方向三：角色声线工坊 / GPT-SoVITS 产品化 PRD

### 7.1 功能定位

当前 GPT-SoVITS 配置页偏工程化。后续应升级为：

> **角色声线工坊：用户为自己的 Live2D 角色创建、训练、绑定和试听专属声音。**

用户感知不应该是“配置 TTS 参数”，而是：

> 我在创造一个有形象、有声音、有情绪表达的二次元写作搭子。

---

### 7.2 核心流程

```text
创建角色
-> 选择/导入 Live2D 模型
-> 上传声音样本
-> 标注情绪参考音频
-> 配置 GPT-SoVITS 模型
-> 试听角色说话
-> 应用到朗读/聊天/协作
```

---

### 7.3 产品概念映射

| 技术项       | 产品化名称          |
| ------------ | ------------------- |
| GPT-SoVITS   | 本地角色语音引擎    |
| `.ckpt`      | GPT 声线理解核心    |
| `.pth`       | SoVITS 声音生成核心 |
| API 地址     | 本地语音引擎连接    |
| 参考音频目录 | 情绪声线素材库      |
| wav 情绪标签 | 情绪声线卡          |
| 默认语速     | 说话节奏            |
| 模型加载     | 唤醒角色声音        |
| TTS 测试     | 让角色说一句话      |

---

### 7.4 情绪声线卡

| 情绪 | 文件命名          | 用途                 |
| ---- | ----------------- | -------------------- |
| 平静 | `【平静】xxx.wav` | 默认朗读             |
| 开心 | `【开心】xxx.wav` | 完成、庆祝、轻松对话 |
| 认真 | `【认真】xxx.wav` | 读 PRD、读技术文档   |
| 温柔 | `【温柔】xxx.wav` | 陪伴、安慰、复盘     |
| 生气 | `【生气】xxx.wav` | 可选，不建议默认启用 |
| 难过 | `【难过】xxx.wav` | 可选，谨慎使用       |

默认策略：

- 正文朗读优先平静/认真。
- 聊天可以使用开心/温柔。
- 写作中不自动播放语音。
- 用户主动触发时才发声。

## 8. 方向四：墨迹回放 Agent PRD

### 8.1 功能定位

墨迹回放不是简单录屏，而是记录写作行为的时间序列：

- 光标移动。
- 输入。
- 删除。
- 选中。
- 跳转。
- 粘贴。
- 停顿。
- 保存。
- 完成。

Agent 要从这些痕迹中读懂用户的写作过程。

> 普通写作工具帮你把字写出来；墨迹回放 Agent 帮你看见自己是怎么写出来的。

---

### 8.2 核心能力

| 能力       | 分析内容                 | 输出               |
| ---------- | ------------------------ | ------------------ |
| 高频修改区 | 哪些句子/段落反复删改    | 修改热点           |
| 流畅度曲线 | 单位时间有效输出变化     | 流畅期/卡顿期      |
| 停顿点分析 | 停顿时长、位置、前后操作 | 卡住的位置         |
| 删除模式   | 删除字、句、段，重写差异 | 是改内容还是改表达 |
| 思路转折点 | 写完某处后跳到另一处     | 发现思路跳跃       |
| 灵光闪现   | 短时间高输出且少修改     | 高光片段           |
| 写作习惯   | 长期 session 模式        | 个性化建议         |

---

### 8.3 回放时间轴标注

| 标记 | 颜色/类型 | 含义               |
| ---- | --------- | ------------------ |
| 高光 | 金色      | 高速输出且少改     |
| 卡顿 | 蓝色      | 长停顿/反复移动    |
| 重写 | 红色      | 大段删除后重写     |
| 转折 | 紫色      | 跳转到新结构位置   |
| 完成 | 绿色      | 保存/发布/标记完成 |

输出应温柔、观察式，不评价好坏。

## 9. Agent 系统深度规划

### 9.1 Agent 的技术挑战拆解

| 难度  | 挑战                   | 具体描述                                                 |
| ----- | ---------------------- | -------------------------------------------------------- |
| 🟢 低 | 时序操作流的存储与回放 | 记录光标、键盘、删除、跳转等事件，按时间戳存储并支持播放 |
| 🟢 低 | 基础统计指标计算       | 字数变化率、删改率、停顿时长、编辑频次等                 |
| 🟡 中 | 语义相似度分析         | 判断两段文本是否语义相关，用于画布隐含连接推荐           |
| 🟡 中 | 写作风格分类           | 识别用户是渐进完善型、顶层设计型还是发散跳跃型           |
| 🟡 中 | 情绪状态推断           | 从删改率、撤销频率、停顿模式推断焦虑/流畅状态            |
| 🟡 中 | LLM Prompt 编排与调度  | 调用大模型进行文本分析、生成提示语、做工具调用           |
| 🔴 高 | 画布空间结构理解       | 理解节点在二维空间中的位置关系、聚类和层次结构           |
| 🔴 高 | 多人实时协作意图推断   | 理解群体行为模式，如共识、分歧、主导者、补充者           |
| 🔴 高 | 开放场景分支决策       | 在分支不可枚举的场景中判断该做什么、什么时候做           |
| 🔴 高 | 低延迟实时推理         | Agent 分析不能阻塞画布操作、输入和协作同步               |
| 🔴 高 | Rust 原生 Agent 运行时 | Rust 生态缺少成熟 Agent 框架，需要自建或深度定制         |

### 9.5 Agent 输出原则

Agent 的价值不是“炫技”，而是“温柔地把复杂过程变得可见”。

允许：

- 可视化回放标注。
- 温和提示。
- 复盘报告。
- 画布关系建议。
- 用户主动请求后的深度分析。

禁止：

- 冷冰冰地报统计。
- 在正文写作中频繁打断。
- 把用户情绪诊断得过于绝对。
- 强制改写正文。
- 未经许可上传隐私内容。

错误示例：

```text
检测到您已停顿 120 秒。
```

推荐示例：

```text
卡在这里了？要不要先把下一句写出来，不必按顺序来。
```

### 11.1 商业化原则

基础陪伴不能收费，收费点应该是更多表达和个性化。

免费必须有：

- 基础 Live2D 陪伴。
- 基础文档节点。
- 基础 TTS/系统语音。
- 基础陪伴关系。
- 基础墨迹回放。

- 更多角色。
- 更多动作。
- 更多服装。

- 更多回忆展示样式。
- 多设备同步。

- 免费用户没有基础陪伴。
- 免费用户关系记录过期。
- 会员成长更快。
- 付费解除断更惩罚。

## 15. 最终产品判断

如果只做画布，花溯像白板。  
如果只做 TTS，花溯像语音助手。  
如果只做 Live2D，花溯像桌宠。  
如果只做 Agent，花溯像普通 AI 写作工具。

> **一个能把文档放进空间、让角色陪你写作、用声音和你交流、并能回放理解你创作过程的二次元桌面写作伴侣。**
