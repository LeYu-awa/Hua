# Live2D 写作陪伴小人：文章、文件夹与角色关系培养

本文件回答策划提出的核心问题：文章和角色之间如何形成培养关系，以及未来从“文章”扩展到“文件夹与文件夹”时，系统如何不推倒重来。

它不是 AI 记忆系统，也不是剧情对话系统。关系培养只来自非正文事件、文档生命周期、文件夹组织行为和用户主动表达，不读取正文、不评价内容、不让小人说话。

## 1. 当前最缺什么

现有 P2 文档已经定义了陪伴回忆、完成记录、动作收藏和写作花园，但还缺少一层更底层的关系模型：

- 角色到底和哪一个对象建立关系：文章、文件夹、项目空间，还是用户本人。
- 一篇文章完成后，角色和这篇文章之间留下什么痕迹。
- 多篇文章放进同一个文件夹后，角色如何理解“这是一个长期项目”。
- 文件夹与文件夹之间如果有关联，角色关系如何迁移、汇聚或继承。
- 这些关系如何带来第二天回访，而不是变成任务、签到或内容监控。

如果不定义这层模型，后续容易变成零散功能：文章有回忆、文件夹有花园、角色有等级，但它们之间没有可策划的关系链。

## 2. 优先级判断

| 能力 | 优先级 | 判断 |
| --- | --- | --- |
| 关系对象模型 | Must for P2 | 没有它，文章、文件夹、角色成长无法统一 |
| 文章-角色陪伴记录 | Must for P2 | 最容易形成“它陪我写完这篇”的情感连接 |
| 文件夹-角色关系 | Should for P2 | 适合项目、专栏、课程、知识库等长期写作 |
| 文件夹之间的关系继承 | Should/P3 | 适合复杂知识管理，但需要等基础关系稳定 |
| 多人共享关系 | Could/P3 | 需要权限、团队策略和协作风控 |
| 角色读懂文章主题 | Won't | 会滑向 AI、内容评价和隐私风险 |

推荐节奏：

```text
P0：不做关系培养，只保留必要非正文事件
P1：允许角色偏好和动作收藏，但不做文章关系
P2：建立文章/文件夹与角色的非压力关系
P3：多人协作下允许共享文件夹 presence 和共同完成记忆
P4：开放主题房间、角色主题资产和创作者扩展
```

## 3. 功能说明

### 3.1 核心定义

关系培养不是“角色理解文章内容”，而是：

> 角色和某个写作容器一起经历了创建、修改、停顿、完成、回访、归档、迁移和再次生长。

写作容器分三层：

| 层级 | 示例 | 关系含义 |
| --- | --- | --- |
| 文章/文档 | 一篇博客、一篇日记、一份 PRD | 它陪我完成这一篇 |
| 文件夹/项目 | 小说章节文件夹、课程笔记、产品方案集 | 它陪我长期做这一组 |
| 空间/花园 | 个人知识库、团队空间、年度写作区 | 它陪我经营这片写作空间 |

角色关系也分三种：

| 关系 | 作用 | 边界 |
| --- | --- | --- |
| 用户-角色关系 | 用户长期使用某个角色形成熟悉感 | 不绑定具体文章内容 |
| 文章-角色关系 | 某篇文章和某个角色共同经历完成/回访 | 不记录标题、摘要、主题 |
| 文件夹-角色关系 | 某个文件夹形成长期陪伴空间 | 不自动推断文件夹语义 |

### 3.2 关系不是绑定，而是陪伴痕迹

不建议把角色强绑定到某篇文章，因为用户会换角色、移动文档、整理文件夹。更推荐“陪伴痕迹”模型：

```text
某个角色曾陪伴某个写作容器
-> 该容器获得一条非正文关系记录
-> 用户再次打开时，可以看到熟悉感或沉淀感
-> 但不阻止用户换角色、移动文件夹或隐藏小人
```

关系记录可以像书签、纪念印章、花盆成长环，不像宠物任务。

### 3.3 文章关系

文章关系适合表达“它陪我写完这篇”。

允许记录：

| 字段 | 说明 |
| --- | --- |
| `documentId` | 运行时或本地关系索引，进入分析前匿名化 |
| `companionId` | 陪伴过该文档的角色 |
| `firstCompanionAt` | 第一次陪伴该文档的时间 |
| `lastCompanionAt` | 最近一次陪伴该文档的时间 |
| `writingSessionCount` | 该角色陪伴过的有效 session 数 |
| `completionCount` | 发布、导出、标记完成次数 |
| `revisitCount` | 间隔较久后的回访次数 |
| `favoriteActionIds` | 用户主动收藏过的动作 |
| `memoryTokens` | 非正文纪念物，例如完成印章、花盆阶段 |

不允许记录：

- 正文。
- 标题。
- 摘要。
- 主题。
- 内容质量。
- 用户情绪。
- “这篇写得很好/很悲伤/很焦虑”。

文章关系状态建议：

| 状态 | 触发 | 表达 |
| --- | --- | --- |
| 初识 | 新文档第一次有效写作 | 角色安静在场，不主动宣告 |
| 陪写中 | 多次有效编辑 | 角色在该文档中沿用更熟悉的低幅动作倾向 |
| 完成过 | 发布、导出或标记完成 | 生成一个非文字完成记忆 |
| 静养中 | 长期未编辑但已完成/归档 | 不催促，回访时有轻微熟悉感 |
| 再生长 | 旧文档被有效修改或扩写 | 可以沉淀“旧枝新芽”式非正文记忆 |

### 3.4 文件夹关系

文件夹关系适合表达“它陪我做这个长期项目”。

文件夹不是文章的简单集合，而是一个长期写作容器。它可以承载：

- 一个专栏。
- 一门课程笔记。
- 一个产品项目。
- 一组小说章节。
- 一个团队知识库栏目。
- 一个年度写作计划。

允许记录：

| 字段 | 说明 |
| --- | --- |
| `folderId` | 文件夹关系索引 |
| `companionId` | 主要陪伴该文件夹的角色 |
| `activeDocumentCount` | 近期活跃文档数 |
| `completedDocumentCount` | 完成文档数 |
| `revisitedDocumentCount` | 回访文档数 |
| `linkedDocumentCount` | 文档之间引用或链接次数 |
| `folderCompanionStage` | 文件夹陪伴阶段 |
| `folderMemoryTokens` | 文件夹级纪念物 |

不允许：

- 自动分析文件夹主题。
- 因文件夹长期未打开而惩罚用户。
- 把文件夹关系做成任务进度条。
- 在正文输入中提示“该回到这个文件夹了”。

文件夹关系状态建议：

| 状态 | 含义 | 体验 |
| --- | --- | --- |
| 萌芽文件夹 | 有少量有效文档 | 文件夹页可出现基础陪伴标记 |
| 稳定项目 | 多篇文档持续活跃 | 角色在文件夹页有固定待机姿态 |
| 成熟合集 | 多篇文档完成/归档 | 可生成合集纪念物或花园区域 |
| 静养书架 | 长期少编辑但仍有价值 | 不降级、不枯萎，像沉淀的书架 |
| 再启动项目 | 旧文件夹重新活跃 | 可出现“重新点亮”的非文字变化 |

### 3.5 文件夹与文件夹之间

后续不一定是文章，而可能是文件夹与文件夹。建议用“关系图”而不是树状绑定。

文件夹之间可以有三类关系：

| 关系 | 示例 | 角色表现 |
| --- | --- | --- |
| 包含 | 一个项目下有多个子文件夹 | 子文件夹成长汇总到项目关系 |
| 引用 | 课程笔记引用资料库 | 形成轻量连接，不转移所有权 |
| 迁移 | 文章从草稿箱移动到发布合集 | 保留原文章关系，新增目标文件夹关系 |

核心原则：

- 文章移动文件夹时，文章-角色关系不丢失。
- 文件夹重命名不影响关系。
- 文件夹合并时，关系可合并为合集记忆。
- 文件夹拆分时，文章关系随文章走，文件夹纪念物保留在原文件夹历史中。
- 关系继承只使用结构事件，不读取文件夹名或文档内容判断语义。

关系图示：

```text
用户
-> 角色
-> 写作容器关系
   -> 文档关系
   -> 文件夹关系
   -> 空间关系
```

## 4. 为什么值得开发

用户价值：

- 让用户感觉角色不是随机动效，而是陪自己写过某些东西。
- 让文章、文件夹和长期项目获得可回看的情感痕迹。
- 鼓励自然回访旧文档和旧文件夹，但不催促。
- 支持知识管理用户和长文创作者，而不只服务单篇文章。

增长价值：

- 文章完成后更容易形成次日回访。
- 文件夹关系能承载更长周期的 DAU/D7/D30。
- 用户会更愿意保留角色，因为它和自己的写作空间有关。

开发成本：

- 需要新增关系模型和关系页/角色页展示。
- 不需要 AI 语义理解，不需要正文处理。
- 可以复用 P2 回忆、写作花园和文件夹统计。

性能影响：

- 关系更新必须在 session 结束、完成、回访、移动文件夹等低频事件后异步发生。
- 正文输入链路只记录本地聚合事件，不写远端关系。
- 文件夹关系汇总按批处理或后台任务计算。

商业价值：

- 适合会员扩展更多纪念物样式、文件夹主题、角色主题房间、收藏空间。
- 不适合把基础文章关系或文件夹关系做成会员专属。
- 付费点应是“更多表达和展示”，不是“免费用户没有关系沉淀”。

## 5. MVP 方案

P2 MVP 建议做“文章关系 + 文件夹关系的最小闭环”。

### 5.1 文章关系 MVP

范围：

- 每篇文档可生成一个 `CompanionDocumentBond`。
- 只记录陪伴 session 数、完成次数、回访次数、最近陪伴角色。
- 发布、导出、标记完成后生成一个非正文完成记忆。
- 用户主动打开角色页/回忆页时展示。
- 正文输入中不展示关系变化。

体验：

| 场景 | 表达 |
| --- | --- |
| 第一次有效写作 | 无提示，只建立关系 |
| 多次回到同一文档 | 角色沿用更熟悉的低幅待机倾向 |
| 完成文档 | 低幅庆祝后，异步生成纪念物 |
| 久未打开后回访 | 角色保持熟悉待机，不说“你回来了” |
| 旧文档重新修改 | 生成“再生长”类非文字纪念 |

### 5.2 文件夹关系 MVP

范围：

- 每个文件夹可生成一个 `CompanionFolderBond`。
- 汇总该文件夹下活跃文档数、完成文档数、回访文档数。
- 文件夹页或写作花园页展示文件夹关系阶段。
- 文件夹关系只在用户主动进入文件夹页、角色页或花园页时展示。

体验：

| 场景 | 表达 |
| --- | --- |
| 文件夹内多篇文档持续活跃 | 文件夹关系从萌芽进入稳定项目 |
| 文件夹内多篇文档完成 | 生成合集纪念物 |
| 文件夹长期未编辑但已归档 | 进入静养书架，不衰败 |
| 旧文件夹重新活跃 | 生成低频再启动纪念 |

### 5.3 不做

- 不做角色读文章。
- 不做文章内容标签。
- 不做“这篇文章和角色很合拍”的 AI 判断。
- 不做文件夹断更惩罚。
- 不做每日照顾文章/文件夹。
- 不在正文输入中弹成长提示。
- 不用小人台词解释关系变化。

## 6. 后续扩展

P2 后续可以扩展：

- 文章纪念册。
- 文件夹主题房间。
- 项目花园区域。
- 角色陪伴地图。
- 文件夹关系图谱。
- 文档迁移纪念。
- 多角色共同陪伴历史。

P3 可以扩展：

- 多人文件夹 presence。
- 团队项目的公共完成记忆。
- 共享文件夹的集体纪念物。
- 协作者共同回访旧项目的低频公共反馈。

P4 可以扩展：

- 文件夹主题皮肤。
- 角色主题房间资产。
- 创作者制作的纪念物样式。
- 项目空间装饰包。

所有扩展仍然必须遵守：

- 不读正文。
- 不说话。
- 不催促。
- 不把关系变成任务。
- 不把基础关系沉淀做成会员专属。

## 7. 是否适合作为会员功能

基础关系培养不适合做会员功能。

免费必须有：

- 文章-角色基础关系。
- 文件夹-角色基础关系。
- 基础完成记忆。
- 基础回访记忆。
- 基础关系页或花园页展示。

会员可以有：

- 更多纪念物样式。
- 更多文件夹主题房间。
- 更多角色陪伴地图展示样式。
- 更大的动作和纪念物收藏空间。
- 多设备同步和备份。
- 高级筛选、整理和导出展示卡。

不能做：

- 会员才记录文章关系。
- 会员才记录文件夹关系。
- 会员关系成长更快。
- 免费用户关系记录过期消失。
- 付费解除文件夹沉寂或断更惩罚。

## 8. 技术实现建议

### 8.1 数据模型

```ts
type CompanionBondScope = 'document' | 'folder' | 'space';

type CompanionBondStage =
  | 'new'
  | 'familiar'
  | 'completed'
  | 'resting'
  | 'revisited'
  | 'regrowing';

interface CompanionBondBase {
  id: string;
  userId: string;
  companionId: string;
  scope: CompanionBondScope;
  targetId: string;
  stage: CompanionBondStage;
  writingSessionCount: number;
  completionCount: number;
  revisitCount: number;
  memoryTokenIds: string[];
  firstCompanionAt: string;
  lastCompanionAt: string;
  updatedAt: string;
}

interface CompanionDocumentBond extends CompanionBondBase {
  scope: 'document';
  lastCompletionActionId?: string;
}

interface CompanionFolderBond extends CompanionBondBase {
  scope: 'folder';
  activeDocumentCount: number;
  completedDocumentCount: number;
  linkedDocumentCount: number;
}
```

### 8.2 事件来源

允许事件：

```text
document_created
document_effective_session_end
document_published
document_exported
document_mark_done
document_archived
document_revisited
document_moved_folder
folder_created
folder_opened
folder_archived
folder_documents_completed
document_link_created
```

禁止事件：

```text
document_text_changed_raw
document_title_text
selected_text
clipboard_text
semantic_topic_detected
emotion_detected
quality_score_generated
```

### 8.3 更新时机

```text
输入中
-> 不更新远端关系

session 结束
-> 异步汇总文章关系

完成/发布/导出/归档
-> 异步生成完成记忆

打开角色页/回忆页/花园页
-> 拉取并展示关系摘要

文件夹移动/合并/拆分
-> 后台任务重算文件夹关系
```

### 8.4 展示入口

| 入口 | 展示内容 | 限制 |
| --- | --- | --- |
| 角色页 | 近期陪伴过的文章/文件夹关系摘要 | 不展示正文标题，可用用户可见文档名由主产品渲染 |
| 回忆页 | 完成记忆、回访记忆、再生长记忆 | 不评价内容 |
| 写作花园 | 文件夹区域、项目花园、纪念物 | 不反向打断正文 |
| 文件夹页 | 文件夹关系阶段和项目纪念物 | 团队空间需遵守权限 |

### 8.5 隐私和权限

- 关系数据不保存正文、摘要、主题、质量和情绪。
- 团队文件夹关系默认只展示给有权限访问该文件夹的成员。
- 私人文档关系不能进入团队看板。
- 团队看板只看聚合，不展示单个成员和单篇文章的关系轨迹。
- 用户关闭小人后，停止新增关系事件，但保留已有关系记录，除非用户主动清除。

## 9. 推荐给策划的结论

建议把“文章和角色之间的培养”定义为：

> 角色陪伴某个写作容器走过一段生命周期后，留下非正文、非评价、可回看的陪伴痕迹。

不要把它设计成：

- 角色读懂文章。
- 文章养角色。
- 用户每天照顾文章。
- 文件夹断更惩罚。
- 小人通过台词回忆过去。

更适合的产品表达是：

```text
文章是一盆花。
文件夹是一片小花圃或一个项目房间。
角色不是来评价花长得好不好，
而是陪你把它种下、养成、暂时放下、以后再回来看看。
```
